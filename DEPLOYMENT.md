# Deployment Guide

**Stack:** Neon PostgreSQL · Render (API + Redis) · Vercel (Frontend)

---

## Overview

| Service | Provider | Notes |
|---------|----------|-------|
| Frontend (Next.js) | Vercel | Auto-deploys from `main` |
| Backend (NestJS) | Render | Web Service + Redis |
| Database | Neon PostgreSQL | Serverless Postgres |
| Queue | BullMQ | Uses Render Redis |
| File assets | Vercel CDN | Static files in `public/` |

---

## 1. Database — Neon PostgreSQL

1. Sign up at [neon.tech](https://neon.tech)
2. Create a new project → pick a region close to your Render region (Oregon / US East)
3. Copy the **Connection String** from the dashboard — it looks like:
   ```
   postgresql://user:pass@ep-xxx.us-east-1.aws.neon.tech/dbname?sslmode=require
   ```
4. Keep this — you'll paste it as `DATABASE_URL` in both Render and locally

### Run Migrations

After setting `DATABASE_URL`, run once locally or via Render shell:
```bash
cd apps/api
npx prisma migrate deploy
```

> Neon requires `?sslmode=require` at the end of the connection string. The Prisma schema already has `driverAdapters` enabled for Neon compatibility.

## 2. Backend — Render

### Deploy with Blueprint (render.yaml)

1. Push your repo to GitHub
2. Go to [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
3. Connect your GitHub repo, point at `apps/api/render.yaml`
4. Render creates:
   - **novimp-api** — NestJS web service
   - **novimp-redis** — Redis instance (for BullMQ queues)

### Set Environment Variables on Render

Go to **novimp-api → Environment** and add:

| Variable | Value |
|----------|-------|
| `DATABASE_URL` | Your Neon connection string |
| `FRONTEND_URL` | Your Vercel URL (e.g. `https://novimp.vercel.app`) |
| `APP_URL` | Your Vercel URL |
| `RESEND_API_KEY` | From [resend.com](https://resend.com) |
| `RESEND_FROM_EMAIL` | `noreply@yourdomain.com` |
| `TELEGRAM_BOT_TOKEN` | From @BotFather |
| `TELEGRAM_ADMIN_IDS` | Your Telegram user ID (from @userinfobot) |
| `HELEKET_MERCHANT_ID` | From Heleket dashboard |
| `HELEKET_PAYMENT_KEY` | From Heleket dashboard |
| `AUTOSMO_API_KEY` | Your AutoSMO key |
| `PROXYSELLER_API_KEY` | Your ProxySeller key |
| `ONLINESIM_API_KEY` | Your OnlineSIM key |
| `JWT_SECRET` | Auto-generated by render.yaml |
| `JWT_REFRESH_SECRET` | Auto-generated by render.yaml |
| `ENCRYPTION_KEY` | Auto-generated by render.yaml |

> `REDIS_URL` is **auto-configured** from the Redis service — no need to set it manually.

### After First Deploy

Run Prisma migrations via Render Shell:
```bash
npx prisma migrate deploy
```

Then seed your providers:
```bash
node add-provider.js
node add-onlineproxy.js
```

### Verify

```
https://your-api.onrender.com/health
# → {"status":"ok"}
```

## 3. Frontend — Vercel

### Deploy

1. Go to [vercel.com/new](https://vercel.com/new)
2. Import your GitHub repository
3. Vercel will auto-detect `vercel.json` at the root — it sets:
   - **Root Directory**: `apps/web`
   - **Framework**: Next.js
4. Set environment variables:

| Variable | Value |
|----------|-------|
| `NEXT_PUBLIC_API_URL` | `https://your-api.onrender.com` |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | Your bot's username (without @) |

5. Click **Deploy**

### Custom Domain (optional)

- Vercel: Project Settings → Domains → Add domain
- Update `FRONTEND_URL` on Render to match your custom domain

## 4. Post-Deploy Checklist

- [ ] `DATABASE_URL` set on Render with `?sslmode=require`
- [ ] `npx prisma migrate deploy` run after first deploy
- [ ] Providers seeded with `node add-provider.js`
- [ ] `FRONTEND_URL` on Render matches your Vercel URL (for CORS)
- [ ] `NEXT_PUBLIC_API_URL` on Vercel points to your Render API
- [ ] Telegram bot token set + admin IDs configured
- [ ] Heleket webhook IP `31.133.220.8` whitelisted if using a reverse proxy
- [ ] Health check passing: `https://your-api.onrender.com/health`

## 6. Neon + Prisma Notes

The schema already has the Neon driver adapter configured:
```prisma
generator client {
  provider        = "prisma-client-js"
  previewFeatures = ["driverAdapters"]
}
```

If you see SSL errors, make sure your `DATABASE_URL` ends with `?sslmode=require`.

For connection pooling on Neon, use the **pooled connection string** (Neon provides both — use the pooled one for the API):
```
postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/dbname?sslmode=require
```

## 7. Render Free Tier Notes

- Free web services **spin down after 15 minutes of inactivity** — first request after sleep takes ~30s
- Upgrade to **Starter ($7/mo)** to keep the API always on
- Redis on free tier persists data but has memory limits — Starter plan recommended for production
